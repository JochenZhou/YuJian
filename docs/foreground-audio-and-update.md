# 前台音频与在线升级

## 本机音频策略（1.9.2）

- 玉简任意页面可见时允许本机播放。播放器与首页切换、应用内对话框不会暂停输出。
- 按 Home、返回退出或切换到其他全屏 APP 后，仅挂起这台设备的本地输出，释放音轨、音频焦点及播放用唤醒锁。
- 不向 Music Assistant 发送暂停、停止或静音，不改变同步组和原有音量/静音设置；通知服务与 Sendspin 连接继续运行。
- 后台音频不进入待播队列。手动返回玉简后，用新音频的服务器时间戳重新预缓冲并对齐当前组位置，不补播后台歌曲片段。
- 后台切歌、重连和音量指令不会恢复本机音频，也不会自动弹回播放器。开机仅启动服务时同样保持本机不出声。
- 此策略适用于安装本版本的所有设备，不仅限于 Android 6。

HTTP 状态中 `playing` 仍表示组播放意图。后台的 `output_playing=false`、`output_suspended=true` 和 `sync_state=background_suspended` 表示本机因退后台而挂起，不是音频故障。时钟与进度仍可更新。

## Android 6 在线升级

新下载使用应用私有缓存的 `updates` 目录。安装时通过只读 `content://` URI 和临时读取授权交给系统安装器，API 23 也不再使用 `file://`，无须申请公共存储读写权限。

下载完毕先检查文件格式、已知文件长度、包名、版本号和签名。系统安装器仍负责最终验签与确认安装。Android 6 如被 ROM 限制，需要在系统设置允许未知来源；Android 8 以上未授权时先进入本应用的未知来源设置，授权返回后继续安装。

失败提示分别指出下载/保存、文件校验或安装交接环节。不能仅根据“升级失败”断定缺少存储权限；机型安装器兼容性仍需要真实设备确认。

**一次性升级注意：** 已安装的旧版本仍然使用旧安装交接代码，新 APK 无法修复它自身尚未运行前的安装流程。若旧版本在线升级失败，需先手动安装本次同签名 APK（覆盖升级、保留数据），以后升级才会使用新流程。

## 验证边界

自动化测试覆盖 API 23/24 的安装 Intent 与 Provider、API 26/34 未知来源授权，以及可见性、本地输出生命周期、后台队列丢弃与协议设置保留。设备驱动输出与厂商安装器仍需实机验证；未获授权不连接电视。
